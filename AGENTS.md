# Race Star — инструкции для агента

Клон-ремейк `com.coolcatsgames.racestaridle` на Phaser 3 + Vite (+ Capacitor для APK).
Разбор оригинала — в `teardown/FINDINGS.md`. **Читай его перед изменением баланса.**

## Структура

```
src/config/     palette.js (цвета/шрифт), balance.js (числа экономики и гонки),
                classes.js (6 классов + апгрейды), drivers.js (редкости, гача,
                тренировка), career.js (карьерный драйвер + скилл-дерево)
src/utils/      format.js (219M / $1.21K / 00:59), rng.js (сидированный ГПСЧ)
src/systems/    GameState, SaveSystem, UpgradeSystem, RaceSimulation,
                RaceRewards (начисление за финиш), RaceController,
                DriverSystem (математика драйвера), Roster (состав/резерв/гача),
                CareerSystem (уровни, очки, свод скиллов)
src/ui/         widgets (Button/Bar/panel/label), ScrollView (скролл с маской),
                TopBar, RacePanel, TrackView, UpgradeCard, UpgradeGrid,
                BottomNav, Toasts, ClassesModal, drivers/ (модалка драйверов),
                career/ (дерево скиллов)
src/scenes/     BootScene (сплэш), MainScene (главный экран)
tools/sim/      балансный стенд (см. ниже), tools/smoke.mjs — тапы в Chrome,
                tools/shot.mjs — скриншот экрана (ловит наложения)
```

Файл > 200 строк — делим. Ассетов нет: весь UI рисуется примитивами Phaser.

## Железные правила

1. **Числа только в конфигах** (`balance.js`, `classes.js`, `drivers.js`).
   Никаких магических констант в системах и UI.
   Каждое число помечено источником: `[F]` — снято с кадров оригинала,
   `[~]` — реконструкция формы формулы, `[X]` — наш баланс. Метку не терять.
2. **Систему не смешивать с Phaser.** В `src/systems/` нет ни одного объекта сцены —
   только чистые данные и математика. Это позволяет прогонять баланс симуляцией.
3. **Симуляция гонки сидированная** (`SeededRandom`). Не звать `Math.random()` внутри
   `RaceSimulation` — иначе заезд перестанет воспроизводиться по сиду.
4. **Кнопки срабатывают на `pointerup`** и только если палец не уехал >12px.
   Сетка апгрейдов скроллится, `pointerdown` покупал бы при перетаскивании.
5. **Скролл слушается на `scene.input`, не через Zone.** Zone с `topOnly`
   перехватывает клики у кнопок внутри карточек — уже наступали на эти грабли.
6. Состояние сохраняется в localStorage (`SaveSystem`, ключ `race-star-save`,
   поле `version`). Меняешь форму сейва — поднимай `VERSION`.
7. **Награды за финиш — только в `RaceRewards.applyRaceResult`.** Их считает и
   игра, и балансный стенд; вторая копия формул рассинхронизируется молча.
8. **Прибавка от экономических апгрейдов ПЛОСКАЯ, цена — экспонента.**
   Растущая прибавка при растущей цене уводит доход в бесконечность: первый
   же прогон стенда дал `$NaN` и `1.6e+168` фанатов на четвёртой минуте.
9. **Тронул числа в конфигах — прогони `npm run sim`.**
   На глаз кривая идлера не проверяется.
10. **Hit-area контейнера задаётся ОТ ЛЕВОГО ВЕРХНЕГО УГЛА.** Phaser перед
   проверкой прибавляет к точке `displayOrigin` (= width/2, height/2). Значит
   для содержимого, нарисованного от 0,0, прямоугольник — `(w/2, h/2, w, h)`,
   а для центрированного (Button) — `(0, 0, w, h)`. Написанный «интуитивно»
   `(-w/2, -h/2, w, h)` уводит зону нажатия на полширины влево: правая
   половина кнопки не нажимается, а пустое место слева — нажимается.
11. **Не занимать поля `list` и `name` у наследников Container.** `list` —
   это массив детей Phaser, присвоение убивает контейнер с загадочным
   `array.indexOf is not a function`.
12. **Содержимое `ScrollView` позиционируется от угла списка,** а не экрана:
   `scroll.inner` уже лежит внутри контейнера, сдвинутого на (x, y).
13. **Свод скиллов кэшируется — сбрасывай кэш при КАЖДОЙ мутации.**
   `state.careerFx` дёргается из `incomePerSec`, то есть несколько раз за
   кадр. Кэш живёт в `_fx`, чистят его `spendSkill`, `resetCareerSkills` и
   **сеттер `activeClass`**: дерево у каждого класса своё, и без сеттера
   смена класса тащила бы чужие проценты.
14. **Апгрейд, невидимый для оценщика, — апгрейд-ловушка.** Правило шире
   `pg` фанатов: если `ratePerSec` не видит эффект (приз, фанаты, лига), бот
   не купит узел никогда, и игроку он тоже не нужен. Прежде чем объявлять
   узел слабым, прогони его принудительной раскладкой (`fastSim({career})`) —
   `Crowd Work` так оказался не ловушкой, а на 63% ЛУЧШЕ жадного бота.
   Горизонт оценки для карьеры отдельный (`CAREER_HORIZON_RACES`): очко
   вкладывается навсегда и меряется остатком игры, а не 14 часами.
15. **Математика заезда живёт в одном файле — `src/systems/RaceModel.js`.**
   Потребителей три: визуальная гонка, быстрая модель стенда и аналитический
   `placeDist`, по которому решает бот. Копия формулы в любом из трёх означает,
   что баланс подбирается по одной игре, а игрок катается в другой.
16. **Места в заезде НЕ независимы.** Форма и режим разыгрываются игроку один
   раз на всю гонку, поэтому свёртка девяти независимых `beatProb` завышает
   разброс и занижает победы — при силе/лиге 1.3 давала 7% против 26%
   у симуляции. `placeDist` фиксирует собственный результат и интегрирует по
   нему. Ошибка прожила три этапа подбора незамеченной: три модели сверяются
   `npm run sim:race`, и до Этапа 4 в сверке было только две строки из трёх.

## Что уже сделано

**Этап 1.** Непрерывные гонки 60 с / 10 участников, карта трассы с точками,
сетка апгрейдов (4 боевых + 4 экономических + 2 трофейных на класс), пассивный
доход, фанаты, призовые, гемы с дневным капом, трофеи, сезоны и лиги, 6 классов
с разблокировкой, офлайн-доход, буст 2x, сохранение.

**Этап 2 — драйверы.** Пятёрка `STARTERS (5)` на класс, резерв, замена в
составе, тренировка (+10% от базы за уровень, опыт корма переносится целиком),
merge дубликатов в звёзды, продажа, две гачи с pity 15 и 13, автосостав.
Сила команды теперь = сумма статов пятёрки, проценты апгрейдов идут поверх;
лестница лиг продлена с 8 до 14 ступеней под вторую ось силы.

**Этап 3 — карьерный драйвер.** Свой драйвер на класс, XP за гонки в этом
классе, очко навыка за уровень (Lv.60 к концу 700-часового горизонта),
дерево из 10 узлов в 4 ярусах на 80 рангов при 59 очках, сброс за гемы.
Драйвер выходит на трассу шестым: его статы прибавляются к сумме пятёрки.
Вход — аватар в шапке. Это первая ветка, где есть РЕШЕНИЕ, а не «покупай что
дешевле»: половина узлов с минусом, взять всё нельзя.

**Этап 4 — ядро заезда.** Заезд разыгрывает на старте, какой стороной
подготовки он решается: с вероятностью `attackWeight` в дело идёт offense
(«обгон»), иначе defense («удержание»). Раскладу вернули смысл — оптимум едет
по силе игрока: догоняющему выгоден перекос, фавориту ровная сборка, цена
ошибки около 20% очков сезона в обе стороны. `Counter Force` [F] вернулся в
дерево, проценты `Glass Cannon` смягчены (перекос теперь чего-то стоит).
Заодно починен `placeDist` (см. правило 16) и на главный экран выведено, какая
сторона решает текущий заезд, — иначе механику не увидеть.
Замер ландшафта расклада — `node tools/sim/split.js`.

## Чего ещё нет

Гараж и машины, гир, уникальные драйверы (`Unique Cores`), PvP-арена,
турниры, клубы, Season Pass, магазин, коллекции.
Вкладки 2, 4, 5, 6 нижнего меню — заглушки.

**Известные расхождения с оригиналом** (шаг 0 дорожной карты, замерены
`npm run diff`, чинятся на шаге 1): у нас тёмная тема — в оригинале светлая
(`#F6F9FC` фон, `#FFFFFF` карточки, `#2465E4` кнопка); интерфейс смешан
русско-английский; карточка класса втрое беднее кадра; нет ленты кругов,
всплывашки фанатов и попапа финиша. Плюс `STARTERS (5)` опровергнут — на
планшетном кадре `STARTERS (9)`, слоты состава открываются.

Долг ядра «защита косметическая» закрыт на Этапе 4: заезд разыгрывает, какой
стороной подготовки он решается (`src/systems/RaceModel.js`), `Counter Force`
вернулся в дерево. Подробности и две отвергнутых замером модели — в шапке
`RaceModel.js`.

## Проверка изменений

```
npx vite build                 # синтаксис и импорты
npx vite --port 3111 &         # затем:
npm run smoke                  # headless Chrome: тапы по живому UI
npm run shot [main|career|drivers|classes]   # скриншот: наложения smoke не видит
npm run diff [экран|all]       # наш экран и кадр оригинала бок о бок
npm run sim                    # баланс на 700 игровых часов
npm run ref:pull               # перекачать кадры витрины, если ref/ опустел
```
Референс — `teardown/ref/`, что на каком кадре — `ref/index.json`. Там же
список экранов, которых **нет ни на одном публичном кадре** (проверено по 42
кадрам витрины и 14 роликам канала): для них «как в оригинале» недостижимо в
принципе — логика из локализации билда, композиция наша, всё `[X]`. Не выдавать
это за перенос оригинала.

Драйвер экранов у `shot` и `diff` общий — `tools/screens.mjs`. Иначе «наш
кадр» у скриншотера и у сверки расходится, и сравнивать становится нечего.

Phaser-ошибки видны только в рантайме — после правок UI обязательно прогонять
страницу в браузере и смотреть консоль, а не ограничиваться сборкой.
`window.__game` — ручка для отладки из консоли.

`smoke.mjs` тыкает **настоящими событиями мыши** и находит объекты через
`getBounds()`, а не по зашитым пикселям. Все найденные до сих пор баги UI были
именно во входном слое (Zone с topOnly, покупка при протяжке, смещённая
hit-area) — вызовами методов напрямую они не ловятся.
